================================================================================
                      ARCHITECTURE & PATTERNS
================================================================================

✅ FOLLOWS FEATURE #1 CONSISTENCY:

Caching:
  Level 1: Redis with user-scoped keys
  Level 2: Database indexes on user_id, created_at
  Level 3: In-memory LRU fallback
  Strategy: Graceful degradation if cache unavailable

Pagination:
  Approach: Offset-based limit/offset
  Default: 50 records per page
  Maximum: 100 records per page
  Response: Returns total count for UI

Error Handling:
  Circuit Breaker: 5 failures → 60s recovery
  Timeout: 5 seconds per query
  Fallback: Cache data or empty results
  HTTP codes: 200, 204, 400, 401, 500, 503

Metrics:
  Tracks: Operation type, success/failure, duration
  Available: Via /metrics endpoint
  Logged: DEBUG, WARNING, ERROR levels

Database:
  Strategy: Indexed queries, eager loading, no N+1
  Indexes required:
    - idx_bookings_user_id_created_at
    - idx_payments_user_id_created_at
    - idx_bookings_travel_date
